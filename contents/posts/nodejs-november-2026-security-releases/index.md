11월 11일 Node.js가 26.13.1, 24.22.3, 22.23.5를 보안 릴리스로 냈다. 공지에 오른 CVE는 16개이고 그중 7개가 High다. High는 전부 `http2`와 `tls` 쪽이다. Node 프로세스가 직접 HTTPS나 HTTP/2를 받는 구조라면 원격에서 프로세스를 죽이거나 다른 연결의 메모리를 응답에 섞어 보낼 수 있는 버그들이라, 이번엔 다음 정기 업데이트까지 미룰 이유가 별로 없다.

> 우리 서비스는 이번 CVE 중 어디에 걸리고, 무엇부터 올려야 할까?

> 이 글은 Node.js 11월 보안 릴리스 공지와 세 버전의 릴리스 노트를 확인해 정리했다. CVE 번호와 심각도는 공지 기준이다.

## 1. 어느 버전으로 올리면 되나

| 릴리스 라인    | 패치 버전 | 함께 올라간 의존성          |
| -------------- | --------- | --------------------------- |
| 26.x (Lithium) | `26.13.1` | llhttp 9.4.4, undici 8.12.4 |
| 24.x (Krypton) | `24.22.3` | llhttp 9.4.4, undici 7.30.2 |
| 22.x (Jod)     | `22.23.5` | llhttp 9.4.4                |

OpenSSL 버전은 바뀌지 않았다. 지원이 끝난 라인에 대해 공지는 "End-of-Life 버전은 보안 릴리스가 나올 때마다 항상 영향을 받는다"고만 적었다. 20.x를 아직 쓰고 있다면 패치가 없는 셈이다.

## 2. High 7건은 어디에 몰려 있나

### HTTP/2 서버

`node:http2`로 서버를 띄운 경우가 가장 많이 걸린다.

| CVE               | 증상                                               | 영향 라인  |
| ----------------- | -------------------------------------------------- | ---------- |
| `CVE-2026-123863` | 세션 정리 중 assertion으로 프로세스 중단           | 24, 26     |
| `CVE-2026-123865` | 종료 중 프로토콜 오류로 메모리·FD 누수             | 22, 24, 26 |
| `CVE-2026-123866` | 스트림 정리 때 해제된 메모리를 상대에게 전송       | 22, 24, 26 |
| `CVE-2026-123874` | `respondWithFile()` 스트림 reset 시 use-after-free | 24, 26     |

`CVE-2026-123863`은 기본 설정 http2 서버에서 요청 본문이 끝나기 전에 응답하는 핸들러만 있으면 인증 없이 터진다고 공지에 적혀 있다. 평범한 코드다. `CVE-2026-123865`는 클라이언트가 `GOAWAY(NO_ERROR)` 뒤에 프로토콜 오류를 보내면 소켓이 `CLOSE_WAIT`에 머문 채 메모리와 파일 디스크립터가 계속 샌다.

### TLS와 HTTPS

개인적으로는 이쪽이 더 걸렸다. **`CVE-2026-123864`는 HTTPS 서버가 자기 힙 메모리를 요청 본문에 복사해 넣는 버그**인데, 공지는 다른 연결의 메모리나 TLS 개인 키까지 섞일 수 있다고 적었다. 조건은 핸들러가 본문이 끝나기 전에 `res.flushHeaders()`를 부르고, 이어서 내용이 있는 `res.end()`를 호출하고, 본문을 그대로 돌려주는 경로가 있는 경우다. 평문 `node:http`는 해당하지 않는다.

나머지 TLS 두 건은 이렇다. `CVE-2026-126051`은 `SNICallback`, `OCSPRequest`, `newSession`, `resumeSession`, `server.addContext()`를 쓰는 TLS 서버를 원격에서 죽일 수 있다. `CVE-2026-123872`는 TLS 1.2 재협상에서 클라이언트가 servername을 바꿔, 클라이언트 인증서 정책이 더 엄격한 호스트로 넘어가는 문제다.

## 3. Medium·Low에서 챙길 것

Medium 여섯 건 중 실무에서 눈에 띄는 건 설정 실수처럼 보이는 것들이다.

- `CVE-2026-123867`: `server.addContext(host, { ca })`처럼 인증서 없이 CA만 넘기면 호스트별 CA가 설치되지 않아, 기본 CA로 신뢰되는 클라이언트가 mTLS를 통과한다.
- `CVE-2026-123877`: 같은 `https.Agent`에서 `ca`를 생략한 요청과 `ca: []` 요청이 세션 캐시 키를 공유해, 기본 정책으로 맺은 세션이 더 엄격한 쪽에서 재사용된다.
- `CVE-2026-123871`: `ERR_PROXY_INVALID_CONFIG` 에러 메시지에 프록시 자격 증명이 그대로 들어가 로그나 크래시 리포트로 새어 나간다.
- `CVE-2026-123868`: HTTP/2에서 비우지 않은 스트림에 쌓인 데이터가 `maxSessionMemory` 계산에서 빠진다.

Low는 대부분 조건이 좁다. `--allow-fs-read=/etc/passwd.*` 같은 와일드카드 허용이 `/etc/passwd` 읽기까지 허용하는 `CVE-2026-106071`은 퍼미션 모델을 샌드박스로 쓰는 경우라면 확인해 볼 만하다.

## 4. 공지와 릴리스 노트가 어긋나는 부분

공지와 릴리스 노트를 나란히 보니 몇 군데가 맞지 않았다.

- 공지는 `CVE-2026-123863`, `123874`, `123868`, `123828`을 24, 26 전용으로 적었지만, 22.23.5 릴리스 노트에도 이 네 건의 수정이 들어 있다.
- 세 릴리스 노트 모두 `CVE-2026-123873`(힙 스냅샷 저장 위치 퍼미션 검사)을 담고 있지만 공지에는 없다.

어느 쪽이든 결론은 같다. 22를 쓰든 24, 26을 쓰든 이번 패치 버전으로 올리면 된다. 영향 라인 표만 보고 "우리는 22라 괜찮다"고 넘기지는 않는 편이 낫다.

### 점검 목록

- 운영 중인 Node 버전을 `node -v`로 확인하고 위 패치 버전과 비교한다
- Docker 이미지라면 베이스 태그가 실제로 새 버전을 받았는지 이미지 안에서 확인한다
- `node:http2` 서버, `respondWithFile()`, `res.flushHeaders()`를 쓰는 코드 경로를 찾아본다
- `server.addContext()`로 호스트별 mTLS를 설정했다면 CA만 넘기는 곳이 없는지 본다
- 20.x 이하가 남아 있다면 이번 기회에 LTS 라인 이전 일정을 잡는다
